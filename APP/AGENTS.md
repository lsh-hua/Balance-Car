# 应用层边界

```text
APP/
├─ MPU6050.C / MPU6050.h      # 采样有效性、校准、配置诊断与姿态解算
├─ mpu6050_calibration.h     # 固定加速度标定参数的只读接口
├─ mpu6050_startup.h         # 有界启动流程与独立写入/读回失败诊断接口
├─ iir_filter.c / .h         # 各传感器通道的二阶低通状态
├─ encoder.c / .h            # 编码器计数与轮速换算
├─ pid.c / .h                # 离散 PID 运算与内部状态
├─ balance.c / .h            # 控制模式、角度/速度串级与电机命令
├─ online_tune.c / .h        # 共用参数单位；历史在线实现默认不编译
└─ motor.c / .h              # 有符号电机命令到 PWM 输出的映射
```

`Core/Src/main.c` 调度采样、姿态更新和控制；`balance.c` 消费姿态与轮速，`motor.c` 执行输出。实验数据和 PC 脚本位于 `E:\桌面\Phase1`。

## 当前运行模式

用户已取消在线调参，并明确选择校准完成后自动运行。默认`ONLINE_TUNING_ENABLE=0`、`BALANCE_CONTROL_ENABLE=1`、`ANGLE_ONLY_TEST_ENABLE=0`；参数在源码固定，串口只发遥测，不启动命令接收、ARM/STOP、回执或心跳。下载/复位前固定车架、两轮离地并准备断电；关闭电脑、串口或采集程序不会停机。

离线驱动由main独立保护：配置/校准/采样健康且姿态有限才运行；相对角严格超过±45°锁存停机，回正不恢复，排障并安全复位后才重新启动。NaN/Inf先于控制计算拒收并锁存IMU故障，遥测角度安全编码；`[IMU] stop=1`表示离线倾倒锁存。协议仍61字节，硬件急停仍靠物理断电。现行步骤见Obsidian Phase5的5.16；历史在线资料仅适用于显式ONLINE1测试变体。

## 校准约束

- 上电静止平均只更新陀螺仪零偏；加速度计中的重力分量是姿态信息。
- I2C 失败和原始加速度三轴全零样本不参与校准或更新滤波；1000 个有效读数完成才设置校准完成标记，静止条件仍由实物测试保证。
- `main.c` 消费采样/配置/校准状态决定是否允许驱动；传感器失败时保留姿态历史，但输出必须停止，诊断零值不能当作新的有效测量。
- 加速度计使用 `MPU6050.C` 中唯一的固定版本参数对象，`mpu6050_calibration.h` 只声明接口；任意上电姿态平均不用于扣除重力。
- 主采样、`Update` 和滤波初始化共用浮点加速度转换，标定在 g 域 IIR 之前完成。芯片原码全零检查先于减偏；只对 filtered 遥测编码饱和，姿态保留完整浮点值。
- raw 加速度通道保留芯片原码，filtered 加速度通道代表固定标定后低通量；陀螺仪 raw 仍是扣启动零偏后的量。两类 raw 契约分别记录。
- 用户2026-10-23确认保留基础参考0°、默认trim=0°；旧-2.07°/+0.2°仅属历史实验。基础参考通过`Control_GetBasePitchMdeg()`统一到毫度，main通过只读`Control_GetPitchReferenceDeg()`消费实际base+trim，避免导出可写全局或复制偏置；当前固定源码值，不能通过串口SET修改。指定0不证明机械直立或质心平衡点已验收。
- 角度环单独测试验证姿态响应，速度环验证零速调节；精确位置保持还需位置反馈。
- 当前默认限幅±3500、P/I/D=300/0/1.8及参考不变；内环2 ms、外环10 ms。初次健康采样即可驱动，不等待电脑连接或许可。
- 前一轮容量对照只将限幅从1000放宽到1500；未触旧限幅的控制计算不变，不能据此保证小角度更硬、转速更低或后倾一定恢复。新版在线参数仅RAM，实际值查回执；不修改IMU故障锁存及驱动死区。
- `pitch_deg`始终保留传感器融合角，控制内部才减`base+trim`；目标角是相对参考的量。当前相对角为Pitch；若以后修改源码trim为2°，相对角变为`Pitch-2°`，不修改Pitch或重新标定传感器。
- 死区是绝对命令小于100时置零，不是摩擦补偿；PWM命令上限不等于转速上限。`balance_output`为限幅后、反号和倾倒保护前的理论量，电机命令遥测仍在驱动死区之前。
- 默认`ANGLE_ONLY_TEST_ENABLE=0`，外环固定P/I/D=0.00375/0/0、目标零速、每5个2 ms tick更新、输出相对目标角±2°。单环测试变体显式设宏为1，其目标相对角与速度环序号才保持0。
- `Control_ResetTuningState`统一清两环历史、输出、外环目标、速度低通与分频，由初始化调用；历史ONLINE1变体SET/ARM也调用。累计速度环序号仅初始化归零；序号连续不证明硬实时达标。
- 闭环由`Control_Loop`读取编码器，不得在main再次读清。当前闭环的累计编码器遥测未更新，不能用其零值断言轮子静止。故障后理论量可能保留旧值，只据有效状态、stop锁存与实际命令判断；离线main锁存倾倒、在线历史变体撤销许可，都不会仅因扶正而恢复驱动。
- main编译期禁止闭环与Phase2阶跃同时启用；两者都能写驱动，只允许一种输出所有者。
- 比较调参结果时记录模式、增益、限幅及测试条件。恢复速度环时同时检查角度输出限幅与 PWM 限幅的变化。
- 速度 PID 自身的输出限幅与实际目标角边界保持一致；PWM 上限独立于单环/串级模式。速度遥测编码越界先限幅，控制仍使用完整浮点值。
- HAL 阻塞 I2C 位于 TIM2 中断期间，SysTick 必须能抢占该中断以推进超时；异常事务仍可能超过2 ms预算，不能将逻辑序号连续当作硬实时证明。
- `main.c` 在启动配置/校准/初始采样失败或运行首次采样失败时锁存故障；后续 TIM2 只保留零输出、时序和遥测，不再访问 I2C。排障并复位后才重新初始化，当前没有自动恢复或自动重新驱动。
- 启动唤醒和整套配置只在定时器启动前有限重试；本轮写入及寄存器读回全部通过后才校准。历史失败保留在独立启动诊断中，不能用历史失败否决已经验证成功的本轮配置。
- `mpu6050_startup.h` 单独承载新增诊断，保留旧GBK头文件编码；`[ISTART]` 的阶段4只表示初始化配置与校准完成，运行有效性继续看 `[IMU]` 和故障锁存。
- `[IMU]` 主循环文本诊断与61字节二进制帧交替发送；寄存器为启动快照，计数为异步状态，PC端不将其当作与每帧严格同步。
- `[ACAL]` 从同一参数对象输出标定版本及定点参数，PC端仅记录，不再施加一次校准。输出与61字节帧交替发送，不改变二进制结构。
- UART 发送检查返回值并保存累计失败数、最近失败状态及剩余字节数；完整包和完整诊断文本是通信验收，IMU 有效性单独验收。

## 验证

当前默认分支必须独立验证：不链接在线函数也能运行、无电脑/心跳依赖、健康自动驱动、编码器单读、61字节帧、相对±45°边界及越界后回正仍停机、NaN/Inf先拒收。旧在线用例须显式编译ONLINE1，不能拿它冒充默认固件。

### 历史可选在线分支（仅ONLINE1）

在线调参只开放角度P/D、trim和100..3500的命令上限；SET须停机整组校验并在控制tick应用，Ki/速度模式/标定/保护角不可下发修改，参数仅RAM。主循环解析CRC命令，中断只缓存字节；UART3接收ISR可抢占TIM2，但不阻塞、不发送。ARM须新epoch、健康且相对角不超过8度，750 ms未PING、IMU故障、超45度或RX错误撤销许可；软件门禁不替代硬件急停，也不证明首个阻塞事务内及时响应。

PWM范围由online_tune.h的ONLINE_TUNE_OUTPUT_LIMIT_MIN/MAX定义，命令入口与Control_ApplyTuning共用；默认3500，旧SET1500/2000兼容，3501拒收。本轮2000→3500只放宽饱和余量，不增加未饱和增益，不改TIM1周期、死区或保护；对应实验记录见Obsidian Phase5的5.12。范围扩大不证明供电、驱动温升或车体稳定性已验收。

trim允许±2000 mdeg（±2°），两处C校验共用online_tune.h常量，PC使用对应统一范围；±2.001°拒绝。基础参考只是只读回执元数据，不属于SET。修改基准或范围后须重新编译下载固件并重启Python；旧固件可能拒绝2°或回显旧基准，不能只更新一端即操作电机。

最终许可检查与Motor_Update的GPIO/CCR提交共用极短PRIMASK临界区，防止RX错误在检查和写输出之间抢占；必须恢复调用前mask，采样/计算/串口处理不放入该区。CRC坏包只丢弃重同步，UART错误/溢出才触发RX故障撤销。

Keil启动栈保留4 KB；旧单环在线版本静态图已知主循环最深808 B，还需计入中断抢占叠加，旧1 KB不足。静态图仍含未知库路径，不等于实测栈水位保证；实机还需验证通信和时序。恢复在线分支是另一个运行模式，必须重新确认安全和操作步骤，不能仅为编译通过修改开关。

### 默认与历史回归入口

回归入口为`E:\桌面\Phase1\p4\test_online_tune_firmware.py`及`test_online_tune_integration.py`：默认ONLINE0产物和自动运行保护分别独立验证，旧协议/main许可用例显式ONLINE1保留。`test_balance_control.py`保留37个显式单环基线，另有12个真实默认离线串级场景；算法夹具不代替main保护集成。

修改校准时，验证不同静止上电姿态下，同一后续姿态的加速度角保持一致，且静止陀螺仪零偏仍被消除。离线测试和语法检查不能代替实车稳定性验收。

固定加速度转换的真实驱动回归入口是 `E:\桌面\Phase1\p4\test_mpu6050_calibration.py`；测试不打开串口。模长接近1 g不能单独证明绝对倾角准确。

修改控制或电机映射后，运行 `E:\桌面\Phase1\p4\test_balance_control.py`；它通过fake HAL执行真实控制、PID、编码器与驱动源码，并提取main真实定时回调、帧/快照及启动锁存表达式验证调度和零输出。测试不执行完整main初始化、不访问串口、不验证真实中断时延或车体动力学，也不授权开启电机。

控制测试的参考与限幅预期取自独立实验设定，不从生产offset生成全部输入。浮点到整数截断允许明确的1计数量化差异；倾倒/故障零输出、实际命令与CCR一致性及最大限幅仍严格验证。调整实验参数时同步对应预期，不能反过来更改用户配置迎合旧测试。
